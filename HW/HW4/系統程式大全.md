## 第1章 系統程式導論

### 1.1 什麼是系統程式

系統程式（System Programming）是指用來開發、維護、控制電腦系統底層運作的程式。與應用程式（Application Programming）不同，系統程式更接近硬體，負責管理計算機的資源，並為上層的應用程式提供執行環境。

典型的系統程式包括：

- **作業系統（Operating System）**：管理硬體資源、提供系統服務
- **編譯器（Compiler）**：將高階語言翻譯成機器碼
- **組譯器（Assembler）**：將組合語言翻譯成機器碼
- **連結器（Linker）**：將多個目的檔結合成可執行檔
- **載入器（Loader）**：將可執行檔載入記憶體中執行
- **直譯器（Interpreter）**：直接執行高階語言程式

### 1.2 系統程式的層次結構

計算機系統可以從上到下分為多個層次：

```
+---------------------+
|   應用程式          |  ← 使用者空間
+---------------------+
|   程式庫（libc）    |
+---------------------+
|   作業系統核心      |  ← 核心空間
+---------------------+
|   韌體（BIOS/UEFI） |
+---------------------+
|   硬體（CPU/RAM）   |
+---------------------+
```

系統程式設計師的工作就是在這些層次之間建立橋樑。

### 1.3 為什麼學習系統程式

1. **理解計算機的本質**：知道程式到底如何在硬體上執行
2. **寫出更好的程式**：了解底層運作原理，能寫出更高效的程式碼
3. **開發基礎設施**：作業系統、編譯器、資料庫等是現代軟體的基石
4. **除錯能力提升**：能從底層追蹤問題根源

### 1.4 本課程的路線圖

本課程（CPU2OS）的路線是從電路到作業系統，一路向上建構：

```
數位電路 → CPU設計 → 組譯器 → C編譯器 → 作業系統
```

這條路線讓我們從零開始，一步步建立起完整的計算機系統。

## 第2章 數位電路與 CPU 架構

### 2.1 數位邏輯基礎

#### 2.1.1 邏輯閘

最基本的數位電路元件是邏輯閘：

| 邏輯閘 | 符號 | 運算 |
|--------|------|------|
| AND | `&` | 兩者皆為 1 時輸出 1 |
| OR | `|` | 至少一個為 1 時輸出 1 |
| NOT | `~` | 輸入為 1 時輸出 0，反之亦然 |
| NAND | `~&` | AND 的相反 |
| NOR | `~|` | OR 的相反 |
| XOR | `^` | 兩者不同時輸出 1 |

#### 2.1.2 組合邏輯

組合邏輯電路的輸出只取決於當前的輸入。常見的組合邏輯電路包括：

- **加法器（Adder）**：將兩個二進位數字相加
- **多工器（Multiplexer）**：從多個輸入中選擇一個輸出
- **解碼器（Decoder）**：將 n 位元輸入轉換為 2^n 條輸出線

#### 2.1.3 序向邏輯

序向邏輯電路的輸出不僅取決於當前輸入，還取決於歷史狀態。關鍵元件是：

- **正反器（Flip-Flop）**：儲存 1 位元資料
- **暫存器（Register）**：多個正反器組合成 n 位元儲存單元
- **計數器（Counter）**：根據時脈訊號計數

### 2.2 CPU 架構概論

#### 2.2.1 指令集架構（ISA）

ISA 是 CPU 與軟體之間的合約，定義了：

- 支援的指令集
- 暫存器架構
- 記憶體定址模式
- 資料類型

常見的 ISA 包含 x86、ARM、RISC-V 等。

#### 2.2.2 CPU 的基本組成

一顆基本的 CPU 包含以下單元：

- **算術邏輯單元（ALU）**：執行算術與邏輯運算
- **控制單元（Control Unit）**：解碼指令並產生控制訊號
- **暫存器檔（Register File）**：儲存運算中間結果
- **程式計數器（PC）**：指向下一條指令的位址
- **指令暫存器（IR）**：儲存當前正在執行的指令

#### 2.2.3 指令執行週期

每一條 CPU 指令的執行都遵循取指-解碼-執行的循環：

1. **取指（Fetch）**：從 PC 指向的記憶體位置讀取指令
2. **解碼（Decode）**：解析指令的 opcode 與運算元
3. **執行（Execute）**：ALU 執行運算，或存取記憶體
4. **寫回（Write Back）**：將結果寫入暫存器

### 2.3 簡單 CPU 設計範例

在 CPU2OS 課程中，我們設計了一個簡單的 CPU，稱為 cpu0。其特點包括：

- 16 位元指令長度
- 8 個通用暫存器（R0-R7）
- 16 位元位址匯流排（可定址 64KB 記憶體）
- 支援基本指令：ADD、SUB、LD、ST、JMP、BEQ 等

#### 指令格式

```
[opcode(4)][rd(3)][rs(3)][rt(3)][imm(3)]
```

或

```
[opcode(4)][rd(3)][addr(9)]
```

## 第3章 組合語言與組譯器

### 3.1 組合語言基礎

組合語言（Assembly Language）是機器碼的人類可讀形式。每一條組合語言指令對應一條機器碼指令。

#### 3.1.1 基本語法

```assembly
; 註解以分號開頭
LABEL:    ; 標籤，代表一個記憶體位址
    ADD  R1, R2, R3    ; R1 = R2 + R3
    LD   R1, [R2]      ; R1 = Memory[R2]
    ST   [R1], R2      ; Memory[R1] = R2
    JMP  LABEL         ; 跳轉到 LABEL
```

#### 3.1.2 定址模式

| 模式 | 範例 | 說明 |
|------|------|------|
| 暫存器定址 | `ADD R1, R2` | 運算元在暫存器中 |
| 立即定址 | `ADD R1, #5` | 運算元在指令中 |
| 直接定址 | `LD R1, [100]` | 運算元在位址 100 |
| 間接定址 | `LD R1, [R2]` | 運算元位址在 R2 中 |

### 3.2 組譯器實作原理

組譯器（Assembler）的任務是將組合語言原始碼轉換為機器碼。

#### 3.2.1 兩遍組譯（Two-Pass Assembly）

大多數組譯器採用兩遍掃描的方式：

**第一遍（Pass 1）**：
- 掃描原始碼，建立符號表（Symbol Table）
- 記錄每個標籤對應的位址

**第二遍（Pass 2）**：
- 再次掃描原始碼
- 查詢符號表，將每條指令組譯為機器碼
- 輸出目的檔（Object File）

#### 3.2.2 符號表

符號表是組譯器的核心資料結構：

```
符號名稱 | 位址 | 類型
---------|------|------
START    | 0x00 | CODE
LOOP     | 0x10 | CODE
DATA     | 0x80 | DATA
```

#### 3.2.3 簡單組譯器範例

```python
# 簡化的組譯器核心邏輯
opcode_table = {
    'ADD': 0b0001, 'SUB': 0b0010,
    'LD':  0b0011, 'ST':  0b0100,
    'JMP': 0b0101, 'BEQ': 0b0110,
}

def assemble(source):
    # Pass 1: 建立符號表
    symbol_table = {}
    address = 0
    for line in source:
        if ':' in line:  # 標籤
            label = line.split(':')[0].strip()
            symbol_table[label] = address
        else:
            address += 1
    
    # Pass 2: 產生機器碼
    machine_code = []
    for line in source:
        if ':' in line:
            line = line.split(':')[1].strip()
        if not line:
            continue
        parts = line.split()
        opcode = opcode_table[parts[0]]

```

機器碼:     0001 001 010 011 000
             |      |   |   |   |
          opcode   rd  rs  rt  imm

## 第4章 C 語言與編譯器

### 4.1 C 語言與系統程式的關係

C 語言被稱為「可攜式的組合語言」，原因在於：

1. **貼近硬體**：可以直接操作記憶體（指標）
2. **效率高**：產生的機器碼接近手寫組合語言
3. **系統程式首選**：作業系統、編譯器、嵌入式系統的主力語言

### 4.2 編譯器的工作流程

```
原始碼 → 詞法分析 → 語法分析 → 語意分析
        → 中間碼產生 → 最佳化 → 目的碼產生
```

#### 4.2.1 詞法分析（Lexical Analysis）

將原始碼分割成一個一個的記號（Token）：

```c
int a = b + 3;
```

轉換為：
```
KEYWORD(int) IDENTIFIER(a) OPERATOR(=) IDENTIFIER(b) OPERATOR(+) INTEGER(3) SEMICOLON(;)
```

#### 4.2.2 語法分析（Syntax Analysis）

根據文法規則，將 Token 串列轉換為抽象語法樹（AST）：

```
      =
     / \
    a   +
       / \
      b   3
```

#### 4.2.3 語意分析（Semantic Analysis）

檢查型別是否正確、變數是否有宣告等語意規則。

#### 4.2.4 中間碼產生

將 AST 轉換為平台無關的中間表示，如三地址碼（Three-Address Code）：

```
t1 = b + 3
a = t1
```

#### 4.2.5 最佳化

對中間碼進行最佳化處理：

- 常數折疊：`a = 2 + 3` → `a = 5`
- 死碼刪除：移除永遠不會執行到的程式碼
- 暫存器配置：有效利用 CPU 暫存器

#### 4.2.6 目的碼產生

將最佳化後的中間碼轉換為目標平台的機器碼或組合語言。

### 4.3 遞迴下降解析器

一種常用的手寫解析器技術：

```c
// 簡單的運算式解析器
int parse_expression() {
    int left = parse_term();
    while (token == '+' || token == '-') {
        char op = token;
        next_token();
        int right = parse_term();
        if (op == '+') left = left + right;
        else left = left - right;
    }
    return left;
}

int parse_term() {
    int left = parse_factor();
    while (token == '*' || token == '/') {
        char op = token;
        next_token();
        int right = parse_factor();
        if (op == '*') left = left * right;
        else left = left / right;
    }
    return left;
}

int parse_factor() {
    if (token == '(') {
        next_token();
        int val = parse_expression();
        expect(')');
        return val;
    } else {
        int val = token_value;
        next_token();
        return val;
    }
}
```

### 4.4 編譯器與系統程式的關係

編譯器本身就是一個重要的系統程式。沒有編譯器，我們就無法有效率地開發其他系統程式（如作業系統）。因此，編譯器的實作是系統程式課程的核心課題之一。

## 第5章 連結器與載入器

### 5.1 目的檔格式

編譯器或組譯器產生的目的檔（Object File）通常包含：

- **標頭（Header）**：檔案格式資訊
- **程式碼段（.text）**：機器指令
- **資料段（.data）**：已初始化的全域變數
- **BSS 段（.bss）**：未初始化的全域變數
- **符號表（Symbol Table）**：外部參考與定義的符號
- **重定位資訊（Relocation Info）**：需要調整位址的位置

### 5.2 連結器的作用

連結器（Linker）將多個目的檔和程式庫結合成單一可執行檔：

```
目的檔1.o + 目的檔2.o + libc.a → 可執行檔
```

#### 5.2.1 符號解析（Symbol Resolution）

連結器需要解析所有符號參考：

- **強符號（Strong Symbol）**：有定義的函式或變數
- **弱符號（Weak Symbol）**：只有宣告沒有定義
- 連結器必須找到每個弱符號對應的強符號

#### 5.2.2 重定位（Relocation）

重定位是調整程式碼中的位址參考，使其符合最終的載入位址：

```c
// 重定位前的指令
JMP 0x0000  // 假設要到達目標

// 連結器計算偏移後
JMP 0x0042  // 實際位址
```

### 5.3 載入器的作用

載入器（Loader）負責將可執行檔載入記憶體並開始執行：

1. **讀取可執行檔標頭**
2. **配置記憶體空間**（程式碼段、資料段、堆疊）
3. **將程式碼與資料複製到記憶體**
4. **執行重定位**（如果需要）
5. **設定堆疊指標**
6. **跳轉到程式進入點**（通常是 `_start` 或 `main`）

### 5.4 動態連結

現代系統大多使用動態連結：

- **靜態連結**：所有程式碼在編譯時就結合成單一可執行檔
- **動態連結**：在執行時才載入共享程式庫（如 .so、.dll）

動態連結的優點：
1. 節省磁碟空間（多個程式共享同一份程式庫）
2. 節省記憶體（程式庫在記憶體中只有一份）
3. 方便更新（只需更新程式庫檔案）

## 第6章 作業系統核心

### 6.1 什麼是作業系統

作業系統（Operating System, OS）是管理電腦硬體與軟體資源的系統程式，提供：

- **資源管理**：CPU、記憶體、I/O 裝置
- **行程管理**：行程的建立、排程與終止
- **記憶體管理**：位址空間配置與保護
- **檔案系統**：資料的持久化儲存
- **使用者介面**：Shell 或 GUI

### 6.2 作業系統的分類

| 類型 | 特點 | 範例 |
|------|------|------|
| 批次處理 | 一次執行一個工作 | 早期大型主機 |
| 分時系統 | 多個使用者輪流使用 CPU | Unix、Linux |
| 即時系統 | 保證在時限內完成 | RTOS、VxWorks |
| 嵌入式系統 | 資源受限的專用系統 | FreeRTOS |
| 分散式系統 | 多台電腦協同工作 | Google OS |

### 6.3 作業系統的核心功能

#### 6.3.1 核心與使用者模式

CPU 提供兩種執行模式：

- **核心模式（Kernel Mode）**：可以執行所有指令，存取所有硬體資源
- **使用者模式（User Mode）**：只能執行受限指令，無法直接存取硬體

這兩種模式的切換透過**系統呼叫（System Call）** 或**中斷（Interrupt）** 來實現。

#### 6.3.2 微核心 vs 單核心

- **單核心（Monolithic Kernel）**：所有核心服務都在同一個位址空間執行（如 Linux）
- **微核心（Microkernel）**：只有最基本的功能在核心中，其他服務在使用者空間執行（如 Minix）

#### 6.3.3 作業系統的啟動流程

```
電源開啟 → BIOS/UEFI → 開機載入程式 → 核心載入 → 初始化 → 啟動第一個行程
```

### 6.4 CPU2OS 中的作業系統

在 CPU2OS 課程中，我們實作了一個簡單的作業系統，包含：

- 基本的行程管理
- 簡易的記憶體管理
- 系統呼叫介面
- 簡單的檔案系統

這個作業系統在我們自己設計的 CPU 上執行，從硬體到軟體都是自己打造的。

## 第7章 中斷與系統呼叫

### 7.1 中斷的基本概念

中斷（Interrupt）是一種讓 CPU 暫停當前工作，轉而處理緊急事件的機制。

#### 7.1.1 中斷的分類

- **硬體中斷**：由外部裝置觸發（鍵盤、計時器、磁碟）
- **軟體中斷**：由程式指令觸發（`INT` 指令）
- **例外（Exception）**：由程式錯誤觸發（除以零、頁面錯誤）

#### 7.1.2 中斷處理流程

```
1. 裝置發出中斷訊號
2. CPU 完成當前指令
3. CPU 保存當前狀態（PC、暫存器等）
4. CPU 查詢中斷向量表（IVT），找到對應的中斷處理程式
5. CPU 跳轉到中斷處理程式
6. 中斷處理程式執行
7. 中斷處理程式執行 IRET 指令
8. CPU 恢復原本的狀態，繼續執行
```

### 7.2 中斷向量表

中斷向量表（Interrupt Vector Table, IVT）儲存了每個中斷號碼對應的處理程式位址：

```
中斷號 | 位址 | 用途
-------|------|------
0      | 0x00 | 除以零
1      | 0x04 | 單步執行
...    | ...  | ...
0x80   | 0x200 | 系統呼叫
```

### 7.3 系統呼叫

系統呼叫（System Call）是使用者程式請求核心服務的標準方式。

#### 7.3.1 系統呼叫的運作流程

```
使用者程式                 核心
    |                     |
    |--- syscall() ------>|
    |                     |--- 檢查參數
    |                     |--- 執行核心功能
    |<--- 返回結果 -------|
    |                     |
```

#### 7.3.2 常見的系統呼叫

| 系統呼叫 | 用途 |
|----------|------|
| `read()` | 從檔案讀取資料 |
| `write()` | 寫入資料到檔案 |
| `open()` | 開啟檔案 |
| `close()` | 關閉檔案 |
| `fork()` | 建立新行程 |
| `exec()` | 執行新程式 |
| `exit()` | 結束行程 |

在 CPU2OS 中，系統呼叫透過軟體中斷實現：使用者程式執行 `INT` 指令，帶入系統呼叫號碼，核心中斷處理程式根據號碼執行對應的服務。

## 第8章 記憶體管理

### 8.1 記憶體層次結構

```
暫存器 (1ns)        ← 最快、最小、最貴
  L1 Cache (2ns)
    L2 Cache (10ns)
      L3 Cache (20ns)
        主記憶體 (100ns)
           SSD (10us)     ← 最慢、最大、最便宜
```

### 8.2 連續記憶體配置

最早的記憶體管理方式：

- **固定分割**：將記憶體分為固定大小的區塊
- **可變分割**：根據行程需求動態分割

可變分割會產生**外部碎片（External Fragmentation）**。

### 8.3 分頁管理

現代作業系統大多使用分頁（Paging）管理記憶體。

#### 8.3.1 基本概念

- **頁框（Page Frame）**：將實體記憶體分為固定大小的區塊（通常 4KB）
- **頁面（Page）**：將邏輯位址空間分為相同大小的區塊
- **頁表（Page Table）**：將邏輯頁面映射到實體頁框

```
邏輯位址 → [頁號 | 偏移量] → 頁表查詢 → 實體位址
```

#### 8.3.2 多層頁表

為了節省記憶體，現代系統使用多層頁表：

```
邏輯位址 → [目錄 | 表格 | 偏移] → 實體位址
```

### 8.4 虛擬記憶體

虛擬記憶體（Virtual Memory）讓每個行程以為自己擁有完整的位址空間：

- **優點**：
  1. 行程隔離：一個行程無法存取另一個行程的記憶體
  2. 簡化記憶體管理：每個行程有連續的位址空間
  3. 可使用比實體記憶體更多的空間

- **實作機制**：分頁 + 頁面置換演算法（LRU、FIFO、Clock）

### 8.5 CPU2OS 中的記憶體管理

CPU2OS 實作了基本的分頁記憶體管理：

```c
// 頁表項目結構
typedef struct {
    unsigned int present : 1;  // 頁面是否存在
    unsigned int rw : 1;       // 讀寫權限
    unsigned int user : 1;     // 使用者模式可存取
    unsigned int frame : 29;   // 實體頁框號碼
} page_table_entry_t;
```

## 第9章 行程與執行緒

### 9.1 行程的概念

行程（Process）是正在執行的程式的實例。每個行程擁有：

- **獨立的位址空間**（程式碼、資料、堆疊）
- **行程控制區塊（PCB）**：儲存行程狀態、暫存器值、排程資訊等
- **資源**：開啟的檔案、訊號處理器等

### 9.2 行程狀態

```
  New → Ready ←→ Running → Terminated
           ↑        |
           └── Blocked ←┘
```

- **New**：行程剛被建立
- **Ready**：準備好執行，等待 CPU
- **Running**：正在使用 CPU
- **Blocked**：等待 I/O 或其他事件
- **Terminated**：行程結束

### 9.3 行程排程

#### 9.3.1 排程演算法

| 演算法 | 特點 |
|--------|------|
| FCFS（先到先服務） | 簡單，但平均等待時間長 |
| SJF（最短工作優先） | 最佳平均等待時間，但無法預知執行時間 |
| RR（循環輪替） | 分時系統常用，公平 |
| Priority（優先權） | 可能造成「飢餓」現象 |

#### 9.3.2 上下文切換

當 CPU 從一個行程切換到另一個行程時，需要：

1. 保存當前行程的狀態（暫存器、PC、SP 等）
2. 載入下一個行程的狀態
3. 更新排程器資料結構

```c
// 簡化的上下文切換
void context_switch(process_t *prev, process_t *next) {
    // 保存 prev 的暫存器
    save_registers(prev->context);
    
    // 載入 next 的暫存器
    load_registers(next->context);
    
    // 更新目前執行中的行程
    current_process = next;
    
    // 切換到新的堆疊
    set_stack_pointer(next->kernel_sp);
}
```

### 9.4 執行緒

執行緒（Thread）是 CPU 執行的最小單位。一個行程可以包含多個執行緒。

#### 9.4.1 執行緒 vs 行程

| 特性 | 行程 | 執行緒 |
|------|------|--------|
| 位址空間 | 獨立 | 共享 |
| 資源開銷 | 大 | 小 |
| 切換速度 | 慢 | 快 |
| 通訊方式 | IPC | 共享記憶體 |

#### 9.4.2 執行緒模型

- **使用者層級執行緒**：核心不知道執行緒的存在，由使用者空間的執行緒程式庫管理
- **核心層級執行緒**：核心直接管理執行緒，Linux 的 NPTL 就是核心層級執行緒

### 9.5 CPU2OS 中的行程管理

在 CPU2OS 中，行程管理包含：

```c
typedef struct {
    int pid;                      // 行程 ID
    int state;                    // 行程狀態
    unsigned int *context;        // 暫存器上下文
    unsigned int *stack;          // 核心堆疊
    page_directory_t *page_dir;   // 頁表目錄
    struct file *files[16];       // 開啟的檔案
} process_t;
```

## 第10章 檔案系統

### 10.1 檔案系統的基本概念

檔案系統（File System）負責組織和管理磁碟上的資料，提供：

- **檔案的建立、讀取、寫入、刪除**
- **目錄結構**（階層式命名空間）
- **存取權限控制**
- **資料完整性保證**

### 10.2 檔案系統的實作

#### 10.2.1 磁碟分割與格式化

磁碟在使用前需要：
1. **分割（Partition）**：將磁碟分為多個邏輯區域
2. **格式化（Format）**：在分割區上建立檔案系統結構

#### 10.2.2 檔案系統結構

```
+------------------+
| 開機區 (Boot)    |
+------------------+
| 超級區塊 (Super) | ← 檔案系統的元資料
+------------------+
| inode 表格       | ← 檔案的元資料
+------------------+
| 資料區塊         | ← 實際的檔案內容
+------------------+
```

#### 10.2.3 inode 與目錄

- **inode**：儲存檔案的元資料（大小、權限、擁有者、資料區塊指標）
- **目錄**：是一張對應表，將檔名映射到 inode 號碼

```c
struct inode {
    int mode;           // 檔案類型與權限
    int uid;            // 擁有者 ID
    int size;           // 檔案大小
    int blocks[12];     // 直接區塊指標
    int indirect;       // 間接區塊指標
    int double_indirect; // 雙重間接區塊指標
};
```

### 10.3 FAT 檔案系統

FAT（File Allocation Table）是一種簡單的檔案系統：

- **FAT12/16/32**：使用不同的位元數來定址叢集
- 使用**檔案分配表**來記錄哪些叢集屬於哪個檔案
- 優點：簡單、廣泛相容
- 缺點：碎片化嚴重、無日誌功能

### 10.4 Unix 檔案系統

Unix 檔案系統的關鍵特性：

- **一切皆檔案**：裝置、socket、pipe 都以檔案的形式操作
- **硬連結與軟連結**：
  - 硬連結：多個檔名指向同一個 inode
  - 軟連結：特殊的檔案，內容是目標檔案的路徑
- **掛載（Mount）**：將不同檔案系統掛載到目錄樹中

### 10.5 CPU2OS 中的檔案系統

CPU2OS 實作了一個簡單的 FAT-like 檔案系統，支援基本的檔案操作：

- `open()` / `close()` / `read()` / `write()`
- 根目錄結構
- 有限的檔案數量（16 個檔案）

## 第11章 輸入輸出系統

### 11.1 I/O 硬體概觀

常見的 I/O 裝置：

| 裝置 | 介面 | 速度 |
|------|------|------|
| 鍵盤 | PS/2、USB | 慢 |
| 滑鼠 | PS/2、USB | 慢 |
| 螢幕 | VGA、HDMI | 中 |
| 硬碟 | SATA、NVMe | 快 |
| 網路卡 | PCIe | 快 |

### 11.2 I/O 控制方式

#### 11.2.1 程式化 I/O（Programmed I/O）

CPU 直接控制 I/O 操作，透過輪詢（Polling）檢查裝置狀態：

```c
// 輪詢鍵盤控制器
while (!(inb(0x64) & 0x01)) {
    // 等待鍵盤資料準備好
}
char key = inb(0x60);
```

缺點：CPU 在等待時被佔用，浪費運算資源。

#### 11.2.2 中斷驅動 I/O（Interrupt-Driven I/O）

裝置完成操作後發出中斷，CPU 暫停當前工作來處理：

```c
// 鍵盤中斷處理程式
void keyboard_interrupt_handler() {
    char key = inb(0x60);
    key_buffer.push(key);
}
```

優點：CPU 在等待時可以執行其他工作。

#### 11.2.3 DMA（直接記憶體存取）

DMA 控制器直接在裝置和記憶體之間傳輸資料，不需 CPU 介入：

1. CPU 設定 DMA 控制器（來源、目的、長度）
2. DMA 控制器執行資料傳輸
3. 傳輸完成後 DMA 控制器發出中斷通知 CPU

### 11.3 裝置驅動程式

裝置驅動程式（Device Driver）是核心中負責管理特定 I/O 裝置的軟體模組：

- 提供統一的介面給上層（如 `read()`、`write()`、`ioctl()`）
- 處理裝置特定的硬體操作
- 管理中斷處理

```c
// 字元裝置驅動程式的介面
struct file_operations {
    int (*open)(struct inode *inode, struct file *file);
    int (*release)(struct inode *inode, struct file *file);
    ssize_t (*read)(struct file *file, char *buf, size_t count);
    ssize_t (*write)(struct file *file, const char *buf, size_t count);
};
```

### 11.4 終端機 I/O

在 CPU2OS 中，終端機 I/O 透過 UART（通用非同步收發器）實現：

- **輸出**：寫入字元到 UART 傳送暫存器
- **輸入**：從 UART 接收暫存器讀取字元（透過中斷）

```c
// 簡化的 putchar
void putchar(char c) {
    while (UART_STATUS & TX_FULL) {
        // 等待傳送緩衝區空出
    }
    UART_DATA = c;
}
```

## 第12章 虛擬化技術

### 12.1 什麼是虛擬化

虛擬化（Virtualization）是在一個實體機器上模擬出多個虛擬機器的技術。每個虛擬機器（VM）可以執行自己的作業系統。

### 12.2 虛擬化的類型

#### 12.2.1 全虛擬化（Full Virtualization）

模擬完整的硬體環境，來賓作業系統不需修改即可執行：

- **優點**：不需要修改來賓 OS
- **缺點**：效能開銷較大
- **範例**：VMware Workstation、QEMU

#### 12.2.2 半虛擬化（Para-Virtualization）

來賓作業系統知道自己正在虛擬環境中執行，透過 Hypercall 與 Hypervisor 通訊：

- **優點**：效能較好
- **缺點**：需要修改來賓 OS
- **範例**：Xen

#### 12.2.3 硬體輔助虛擬化

利用 CPU 的硬體虛擬化延伸（如 Intel VT-x、AMD-V）：

- **優點**：接近原生效能
- **範例**：KVM、Hyper-V

### 12.3 Hypervisor

Hypervisor（虛擬機器監控器）分為兩類：

- **Type 1（裸機型）**：直接執行在硬體上（如 VMware ESXi、Xen）
- **Type 2（託管型）**：執行在作業系統之上（如 VirtualBox、QEMU）

```
Type 1:  Hypervisor → 硬體
Type 2:  應用程式 → OS → Hypervisor → 硬體
```

### 12.4 模擬器與虛擬機器的區別

- **模擬器（Emulator）**：模擬完整的 CPU 指令集和硬體（如 QEMU 使用者模式）
- **虛擬機器（Virtual Machine）**：大多指令直接在實體 CPU 上執行

在 CPU2OS 中，我們常用 QEMU 來模擬我們的 CPU，這是一種模擬器的應用。

## 第13章 編譯器實作入門

### 13.1 為什麼要實作編譯器

實作編譯器是理解系統程式的最佳方式之一。透過親手打造編譯器，你將深入理解：

- 程式語言是如何被機器理解的
- 高階抽象是如何被轉換為低階指令的
- 計算機科學中的經典演算法與資料結構

### 13.2 一個精簡的編譯器

以下是一個將簡單算術運算式編譯為組合語言的編譯器核心：

```python
# 簡單的運算式編譯器
# 支援 +, -, *, /, 數字

tokens = []
pos = 0

def lex(expr):
    global tokens, pos
    tokens = []
    pos = 0
    i = 0
    while i < len(expr):
        if expr[i].isdigit():
            j = i
            while j < len(expr) and expr[j].isdigit():
                j += 1
            tokens.append(('NUM', int(expr[i:j])))
            i = j
        elif expr[i] in '+-*/()':
            tokens.append(('OP', expr[i]))
            i += 1
        else:
            i += 1

def parse_expression():
    """解析加減運算"""
    left = parse_term()
    while pos < len(tokens) and tokens[pos][1] in '+-':
        op = tokens[pos][1]
        pos += 1
        right = parse_term()
        left = ('BINOP', op, left, right)
    return left

def parse_term():
    """解析乘除運算"""
    left = parse_factor()
    while pos < len(tokens) and tokens[pos][1] in '*/':
        op = tokens[pos][1]
        pos += 1
        right = parse_factor()
        left = ('BINOP', op, left, right)
    return left

def parse_factor():
    """解析數字或括號運算式"""
    if tokens[pos][1] == '(':
        pos += 1
        expr = parse_expression()
        pos += 1  # 跳過 )
        return expr
    else:
        val = tokens[pos][1]
        pos += 1
        return ('NUM', val)

def generate_code(ast, registers=['R0', 'R1']):
    """從 AST 產生組合語言"""
    if ast[0] == 'NUM':
        return f"LD {registers[0]}, #{ast[1]}"
    
    if ast[0] == 'BINOP':
        _, op, left, right = ast
        code_left = generate_code(left, registers)
        # 保存左側結果
        code = code_left + "\n" + f"ST [SP], {registers[0]}\nADD SP, SP, #1\n"
        code_right = generate_code(right, registers)
        code += code_right + "\n" + f"LD {registers[1]}, [SP-#1]\nSUB SP, SP, #1\n"
        
        if op == '+':
            code += f"ADD {registers[0]}, {registers[1]}, {registers[0]}"
        elif op == '-':
            code += f"SUB {registers[0]}, {registers[1]}, {registers[0]}"
        elif op == '*':
            code += f"MUL {registers[0]}, {registers[1]}, {registers[0]}"
        elif op == '/':
            code += f"DIV {registers[0]}, {registers[1]}, {registers[0]}"
        return code

# 使用範例
lex("3 + 4 * 2")
ast = parse_expression()
asm = generate_code(ast)
print(asm)
```

## 第14章 作業系統實作入門

### 14.1 從開機到核心

一個最小的作業系統需要：

1. **開機載入程式**：將核心從磁碟載入記憶體
2. **核心進入點**：設定基本執行環境
3. **初始化**：中斷向量表、記憶體管理、行程管理

#### 極簡核心範例（在 CPU2OS 平台上）

```c
// CPU2OS 極簡核心
#include "cpu2os.h"

// 中斷向量表
interrupt_handler_t ivt[256];

// 核心初始化
void kernel_init() {
    // 設定中斷向量表
    for (int i = 0; i < 256; i++) {
        ivt[i] = default_handler;
    }
    ivt[0x80] = syscall_handler;  // 系統呼叫
    
    // 初始化記憶體管理
    pmm_init();  // 實體記憶體管理
    vmm_init();  // 虛擬記憶體管理
    
    // 初始化行程管理
    process_init();
    
    // 建立第一個行程（init 行程）
    process_t *init = create_process(init_task);
    
    // 開始執行行程排程
    scheduler_run();
}

// 系統呼叫處理程式
void syscall_handler(unsigned int syscall_num) {
    switch (syscall_num) {
        case SYS_WRITE:
            // 輸出字串
            break;
        case SYS_READ:
            // 讀取鍵盤輸入
            break;
        case SYS_FORK:
            // 建立子行程
            break;
        case SYS_EXIT:
            // 結束目前行程
            break;
    }
}

// 第一個使用者行程
void init_task() {
    while (1) {
        printf("CPU2OS> ");
        char cmd[64];
        read_line(cmd, 64);
        execute_command(cmd);
    }
}
```

### 14.2 核心開發的挑戰

開發作業系統核心是一項極具挑戰性的任務：

1. **沒有除錯器可用**：在核心開發早期，printf 就是你的除錯器
2. **沒有程式庫**：不能使用標準 C 程式庫，需要自己實作
3. **硬體相依性**：需要深入理解 CPU 和硬體規格
4. **難以重現的錯誤**：時序相關的錯誤（Race Condition）難以追蹤

### 14.3 開發建議

對於想要實作作業系統的初學者：

1. **從模擬器開始**：在 QEMU 等模擬器中開發，可以避免損壞實體機器
2. **逐步增加功能**：先讓核心能夠開機和輸出文字，再逐步加入更多功能
3. **參考現有專案**：
   - [CPU2OS](https://github.com/ccc114b/cpu2os)：本課程的教材
   - xv6：MIT 的教學用作業系統
   - ToA：陳鍾誠老師的《輕量級作業系統》專案
4. **閱讀原始碼**：Linux 核心的原始碼是最好的學習資源

### 14.4 從 CPU2OS 出發

CPU2OS 提供了一條完整的學習路徑：

```
自製 CPU → 自製組譯器 → 自製編譯器 → 自製作業系統
```

這條路徑讓我們真正從零開始，完整理解計算機系統的每一個層次。當你在自己的 CPU 上執行自己寫的作業系統時，那種成就感是無可比擬的。
